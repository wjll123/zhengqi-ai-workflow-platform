# 企查查批量查询

新版为 Mac 本机工具，优先复用 Chrome/Edge 调试窗口中已登录的企查查标签页，也支持 Safari。每份名单最多 100 家，产出股东信息、主要人物、股东出资明细、查询状态、字段说明五张工作表。SVIP 可见内容和官方导出额度以账号页面为准；SVIP 不作为开放平台 API 权限的判断依据。

## 操作

1. 优先选择 Chrome 或 Edge。用页面给出的终端命令启动独立调试窗口，在该窗口登录企查查并打开 `https://www.qcc.com/`，只保留一个企查查标签页，再点击“检测浏览器连接”。Chrome 默认端口 9222，Edge 默认端口 9223；调试窗口使用独立配置目录，可能需要重新登录，日常浏览器无需关闭。也可选择 Safari，Safari 无需设成系统默认浏览器。
2. 进入平台「企业信息工具 → 企查查 · 企业批量查询」。上传 xlsx、xls 或 csv，名称列使用“公司名称”或“企业名称”。仅有一列公司全称也可以。
3. 核对界面的实际企业数量，默认每轮最多 100 家、每次页面访问间隔至少 60 秒（可设为 60–600 秒）。输入文件超过 100 家时要求拆分，不会截断名单。
4. 如需继续旧结果，展开“续查旧结果与同名企业核对”，选择历史结果。若同名企业有多个，可选择含公司名称和统一社会信用代码的辅助表。
5. 点击“开始批量查询”，下方显示当前企业和逐家状态。查询在后台执行，刷新网页不影响查询；本机平台进程需要保持运行。
6. 遇到登录、验证码、访问限制或页面加载超时，自动暂停该批次并保留当前浏览器标签页。人工处理后点击“继续未完成项”。Chrome/Edge 续查会连接原标签页 ID，不会切到另一家企业的标签页；若原标签页已关闭，需恢复原页或新建批次。不会自动重复提交验证。
7. 随时下载当前 Excel。状态明确区分成功、失败、待查询、查询中、待验证。未取得资料时，条数留空；只有页面明确总数为零，才记录为零。

对现有增量清单，A/B 列同名视为已有企业，仅 B 列有值的行视为新增企业。仅在所有相关行符合这一格式时启用此规则。当前目录的副本清单实际包含 77 家新增企业，不能称为 100 家。

## 查询流程与保证范围

公司全称名单 → 去重和信用代码核对 → 单个浏览器工作者 → 搜索结果精确匹配 → 企业详情名称及信用代码复核 → 股东与主要人员总数校验 → SQLite 逐家提交 → 下载 Excel。

- 只读取登录浏览器已经加载的页面资料。解析器与浏览器操作分离，网页变化时可单独修复。
- 用 macOS 文件锁阻止同一数据目录的多个进程同时运行企查查查询。所有网页和旧任务调用入口都使用同一队列。
- 进度保存在 `data/state/qcc/jobs.sqlite3`。每家企业处理后独立提交；异常退出时此前成功结果保留。重新启动后将遗留运行项恢复为可继续状态。
- Safari 使用独立查询窗口；Chrome/Edge 复用用户在调试窗口打开的企查查标签页，不会自动关闭它。续查优先复用已完成人工验证的企业详情页。
- 已有详情链接直接访问并重新核验身份，减少搜索。有信用代码时优先按代码只搜索一次，并在详情页二次核对；没有代码时按名称精确匹配，括号全半角和空格可归一。登记名称不同的情况同时保留原始名单名称和企查查登记名称，在说明中标明。
- 已获取的股东/人员条数必须与页面总数一致。缺字段、分页截断、隐藏数据和无法确认的总数记录为失败；不会把第一页当成全部记录。
- 新版保存企业详情页全部业务字段与脱敏后的源记录；分期出资每期一行。页面未披露字段标为“未披露”，数值 0 原样保留。未识别的新业务字段作为额外列保留。自然人证件号码脱敏。
- 覆盖范围是企业详情页；人物独立档案、持股穿透或历史变更不在该范围内。页面仅返回“人物简介/持股详情”入口而没有正文时，导出明确标注，不能声称取得这些独立页面的全部信息。
- 补齐时保留旧版明细，查询状态和每条明细标注“旧版基础字段，待补齐”；不会以原来的成功状态冒充新版完整字段。只有通过总数核对的新版结果计入“页面字段已补齐”。
- 旧结果导入先核对完整名单、来源链接、字段和明细条数。完整字段成功项保留；旧版基础字段、失败和未完成项续查。基础资料保存在原数据与上一版本快照中。
- 导出先写临时文件，再原子替换同一批次的 Excel，避免下载半写入文件。

查询间隔用于控制频率，不保证免验证。浏览器页面无法提供完整数据时，可使用企查查官方批量导出或另行开通的官方 API。当前版本没有接入未经核实的隐藏接口或收费 API，也不自动购买权益。

## 控制访问频率

- 在每一次搜索或详情导航之前等待，而不是仅在企业之间等待。读取已经打开的页面不触发重新导航。
- 每 10 次页面访问后至少休息 5 分钟。遇到登录、验证、访问限制或页面超时立即暂停，不自动刷新或提交验证。
- 遇阻后的续查间隔翻倍，最高 600 秒；冷却期依次为 15、30、60 分钟。完成验证仍需等剩余冷却结束。
- 访问时间、页数、冷却和增大的间隔保存在 `data/state/qcc/navigation.json`，跨批次、续查和服务重启生效；单个文件锁保证互斥。浏览器调用间隔至少 3 秒，企业查询间隔至少 60 秒。
- 等待可取消，点击暂停后不会继续发出下一次导航。界面显示最早下一次访问时间。
- 控制访问压力可以减少重复请求，但验证次数还受账号、网络与平台策略影响，无法保证不出现验证。

## 新版代码

`app/qcc/` 为唯一采集实现：`sources.py` 处理名单和身份，`extraction.py` 核对页面数据，`chromium.py` 与 `safari.py` 控制浏览器，`jobs.py` 管理持久任务，`workbooks.py` 负责工作流导出，`routes.py` 提供接口。

页面为 `qcc_workspace.html`，交互与样式位于 `qcc-workspace.js` 和 `qcc-workspace.css`。旧版 `app/core/qcc.py`、`qcc_safari.py` 和旧同步采集实现已移除。

验证命令：`./.venv/bin/python3 -m unittest discover -s tests -p 'test_qcc_rebuilt.py'`。
