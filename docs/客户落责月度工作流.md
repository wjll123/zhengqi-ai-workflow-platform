# 客户落责月度工作流

## 落责数据处理

任务中心的「落责数据处理」使用两份月度来源文件：21 各地市落责统计及排名、月度收入正增长客户数量。文件名无需包含账期；同类文件有多份时取最新上传的一份。任务会先检查来源工作表、表头、全省两个维度、地市、客户分级和必需数值。缺表、缺数据或格式不符时直接报错，不生成新文件。

产出为 `月报-客户落责数据处理.xlsx`。它沿用平台内置的原《落责材料数据处理》工作簿，保留以下四张工作表及其表头、颜色、合并单元格和条件格式：

1. `全量统计`：顶部统计区和下方落责来源数据区。
2. `全量收入正增长统计`：顶部统计区、下方统计与正增长来源数据区、右侧全量 PPT 材料区。
3. `集团规上统计`：顶部两个全省维度和地市统计区、下方来源数据区、右侧集团规上 PPT 材料区。
4. `专精特新统计`：同样保留来源数据区和右侧专精特新 PPT 材料区。

因此 PPT 材料是三块工作表内区域，不是另外三张工作表。平台内置模板缺失或结构不符时也会直接报错。

## 输入与产出

平台任务：`monthly_luozhe_audit`，任务中心名称为「客户落责月度工作流对比」。

需要四份同一统计期的文件：

1. 21 各地市落责统计及排名，含「地市总体落责」「集团规上」「专精特新」工作表。
2. 月度收入正增长客户数量，含全省、21 地市和省级行的五级客户数量。
3. 每月更新的落责材料数据处理工作簿，含四张统计工作表及三块 PPT 材料区。
4. 每月更新的客户落责月报，前三页为全量、集团规上、专精特新。

任务生成 Markdown 差异报告，保存在 `data/outputs/`，原文件只读。

## 七步核对

| 步骤 | 来源与目标 | 核对内容 |
| --- | --- | --- |
| 1 | 地市总体落责 → 全量统计 | 地市、客户分级及 18 个明细字段；全省取维度二 |
| 2 | 正增长客户数量 → 全量收入正增长统计 | 23 行、五级客户数量及地市标签 |
| 3 | 集团规上 → 集团规上统计 | 地市、客户分级及明细字段 |
| 4 | 专精特新 → 专精特新统计 | 地市、客户分级及明细字段 |
| 5 | 来源重算 → 全量 PPT 材料 → 月报第 1 页 | 卓越、战略、核心三级共 345 个数值 |
| 6 | 来源重算 → 集团规上 PPT 材料 → 月报第 2 页 | 战略、核心、小计共 276 个数值 |
| 7 | 来源重算 → 专精特新 PPT 材料 → 月报第 3 页 | 战略、核心、小计共 276 个数值 |

人数、客户数按精确值比较。月报比率显示一位小数，比较时允许 0.05 个百分点的显示误差。报告列出差异的地市、分级、指标、处理表单元格及月报表格行。

## 业务口径与交付检查

- 全省落责数据采用来源表的「维度二：产权对应地市是否有实际业务收入判断」。
- 落责准确率 = 准确落责客户数 ÷ 落责数量 × 100%。
- 有客户经理占比 = 有客户经理的直销落责客户数 ÷ 直销落责数量 × 100%。
- 正增长客户占比 = 正增长客户数 ÷ 落责数量 × 100%。
- 战略与核心小计准确率按准确客户数和落责数量汇总后计算。
- 第 1 页处理表末行「省政企」对应月报「政企」；第 2、3 页「省直管客户」对应月报「省管客户」。任务将其视为已知别名，但交付时应核对业务口径。
- 文件内缺少稳定的共同统计期标记，因此任务只记录用户设置的账期，不自动认定四份文件属于同一月份。更新月报表格后仍要根据当期数据复核页首总结。
